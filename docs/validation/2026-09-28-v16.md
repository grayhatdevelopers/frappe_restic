## Found and fixed

- **Backups used the database name as the database user** (`75890aa`). v16 can give a site
  a separate `db_user`; every backup of such a site failed with `Access denied`. Restores also
  carried the backup's `db_user` into the target. Now `db_user or db_name` (v15 has no
  `db_user`), and restores keep the target's own user. Regression test in `test_recovery.py`.
- Drill only: nginx resolves upstreams at startup, so the frontend now waits for backend
  and websocket (as in frappe_docker's Compose).

## Not covered here

- Access by users without System Manager is covered by the Frappe tests in
  `test_restic_backup_settings.py`, not the drill.
- The drill was run on v16 only; v15 is covered by the Docker suite.
